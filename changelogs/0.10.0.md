# 0.10.0

## [BREAKING] `Span` renamed to `Mark`

```
Before:  ::a    →  Span { name: "a", … }
After:   ::a::  →  Mark { name: "a", … }
```

## [BREAKING] `Mark` takes inline content and nests

`Span` was a leaf with no closer: `::name {attrs}` produced a node whose
`children` was specified as `[]` — *"Always empty — no children"*. It could mark
a position but never a range, which made it useless as a hook for any consumer
that wanted to act on the text it referred to.

`Mark` now takes a closer and real children. The syntax is `::name <content>::`,
with `::name::` retained as the empty form so the placeholder role survives.

```
Before:  ::a b::   →  Span { name: "a", children: [] } + Text(" b::")
After:   ::a b::   →  Mark { name: "a", children: [Text("b")] }
         ::a::     →  Mark { name: "a", children: [] }
```

`children` changes from `[]` to `Inline[]` in §14.3, `Mark` moves to the
container list in §1.5, and §5 gains a *Children of `Mark`* row in its
inline-context table.

**§9.4.1 gains a third degradation class.** The section previously stated that
*"`::` (Span) belongs to neither class: it has no closer to scan for."* That is
no longer true. Because the opener (`::name `) is textually distinct from the
closer (`::`), the parser can tell them apart and matches by counting rather
than by taking the first closer:

- while scanning content, a `::` is a nested opener if followed by `ID_LITERAL+`
  and then a space or `::`; otherwise it closes the innermost open `Mark`;
- a `::` with nothing open is literal text.

This makes `Mark` the only inline construct in the language that permits
**same-type nesting**, including of the same name — `::a ::a ::a ::::::` is
three nested `Mark`s. Emphasis, Strong, Highlight, Spoiler and QuoteInline still
forbid it, because they cannot distinguish opener from closer.

## [BREAKING] Multiline tables removed; `Table.kind` removed

Cutdown had two table variants discriminated by `Table.kind`: pipe (`|`) and
multiline (`+-`). The multiline variant is removed. Tables are pipe-only.

```
Before:  +----------+        →  Table { kind: "multiline", … }
         | cell     |
After:   +----------+        →  Paragraph([Text("+----------+")])
         | cell     |           Table { … }
```

Reason for removal: Multiline syntax is still feature-poor and introduces too much 
cognitive overhead in prose. At the same time, it leaves room for misconfiguration 
and pipe misalignment.

## [BREAKING] `+` is no longer a special character

`+` had no meaning outside the multiline table opener and separator rows, and
none outside tables at all.

## [BREAKING] `QuoteBlock.attribution` renamed to `caption`

A `^ ` line after a `QuoteBlock` filled a field named `attribution`, while the
same line after every other captionable block filled `caption`. One construct,
two field names, for a semantic distinction consumers can make themselves from
the parent node's type.

## [BREAKING] `QuoteBlock` supports lazy continuation

§4.6 carried two contradictory rules — *"Every line MUST begin with `>`. No lazy
continuation"* and *"QuoteBlock supports trailing lines without `>` in same way
as Paragraph"* — and its own third example demonstrated the second while the
conformance corpus pinned the first. A parser built from the example and one
built from the corpus disagreed on the same input.

Lazy continuation is now the rule, matching `Paragraph`, `Section` and list-item
continuation. A line without `>` is handed to the quote's current child block and
follows that block's continuation rules. The quote ends at a blank line, the end
of the enclosing container, or end of input.

```
Before:  > First line   →  QuoteBlock { Paragraph("First line") }
         Continued         Paragraph("Continued")
After:   > First line   →  QuoteBlock { Paragraph("First line Continued") }
         Continued
```

## [BREAKING] `Meta` pagination is slot-based, not positional

A `Meta` block filled `Page[0].meta` only when it was the *first pagination-relevant
item* of the document; otherwise it always closed the current Page and opened its
own. The rule was stated twice and incompatibly — §9.5.2 tested position, while
§4.3 tested the slot ("Always fills `Page.meta`. If `Page.meta` is already set,
opens a new Page first") — and no single reading satisfied the corpus, which
required the positional rule for `pagination-meta-after-break-ghost` and the
slot rule for `comment-block-pass-through-page-assembly`.

Position no longer matters. A `Meta` fills the current Page's `meta` slot when that
slot is empty, and opens a new Page only when it is already set.

```
Before:  Para one          →  Page{Para one}, GhostPage, Page{meta, Para two}
         ---
         ~~~yaml
         title: Two
         ~~~
         Para two
After:                     →  Page{Para one}, Page{meta, Para two}
```

```
Before:  Para one          →  Page{Para one}, Page{meta}
         ~~~yaml
         title: One
         ~~~
After:                     →  Page{meta, Para one}
```

Content before frontmatter — paragraphs, comments, anything — no longer creates a
Page. A `Meta` after a PageBreaker fills the Page the PageBreaker opened; the
boundary is the PageBreaker's, and the `Meta` adds none of its own. This also
removes the `##` / `###` asymmetry whereby a licence header written with `##`
split the document in two while the same header written with `###` did not.
