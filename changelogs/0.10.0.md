# 0.10.0

## [BREAKING] `Span` renamed to `Mark`

```
Before:  ::a    →  Span { name: "a", … }
After:   ::a::  →  Mark { name: "a", … }
```

## [BREAKING] `Mark` takes inline content and nests

`Span` was a leaf with no closer: `::name {attrs}` produced a node whose
`children` was specified as `[]` — *"Always empty — no children"*. It could mark
a position but never a range, which made it useless as a hook for any consumer
that wanted to act on the text it referred to.

`Mark` now takes a closer and real children. The syntax is `::name <content>::`,
with `::name::` retained as the empty form so the placeholder role survives.

```
Before:  ::a b::   →  Span { name: "a", children: [] } + Text(" b::")
After:   ::a b::   →  Mark { name: "a", children: [Text("b")] }
         ::a::     →  Mark { name: "a", children: [] }
```

`children` changes from `[]` to `Inline[]` in §14.3, `Mark` moves to the
container list in §1.5, and §5 gains a *Children of `Mark`* row in its
inline-context table.

**§9.4.1 gains a third degradation class.** The section previously stated that
*"`::` (Span) belongs to neither class: it has no closer to scan for."* That is
no longer true. Because the opener (`::name `) is textually distinct from the
closer (`::`), the parser can tell them apart and matches by counting rather
than by taking the first closer:

- while scanning content, a `::` is a nested opener if followed by `ID_LITERAL+`
  and then a space or `::`; otherwise it closes the innermost open `Mark`;
- a `::` with nothing open is literal text.

This makes `Mark` the only inline construct in the language that permits
**same-type nesting**, including of the same name — `::a ::a ::a ::::::` is
three nested `Mark`s. Emphasis, Strong, Highlight, Spoiler and QuoteInline still
forbid it, because they cannot distinguish opener from closer.

## [BREAKING] Multiline tables removed; `Table.kind` removed

Cutdown had two table variants discriminated by `Table.kind`: pipe (`|`) and
multiline (`+-`). The multiline variant is removed. Tables are pipe-only.

```
Before:  +----------+        →  Table { kind: "multiline", … }
         | cell     |
After:   +----------+        →  Paragraph([Text("+----------+")])
         | cell     |           Table { … }
```

Reason for removal: Multiline syntax is still feature-poor and introduces too much 
cognitive overhead in prose. At the same time, it leaves room for misconfiguration 
and pipe misalignment.

## [BREAKING] `+` is no longer a special character

`+` had no meaning outside the multiline table opener and separator rows, and
none outside tables at all.

## [ADDITIVE] CDN-0031 — `Mark` nesting depth exceeded

Nesting needs a bound. Maximum `Mark` depth is **8**. An opener at depth 9 emits
CDN-0031 (warning).
